Error Handling Strategy

Section titled “Error Handling Strategy”

Agents should implement robust error handling:

  1. 401 → API key is invalid. Stop and request a new key.
  2. 403 (endpoint) → Wrong endpoint. Check the API reference.
  3. 403 (resource) → Wrong resource ID. Verify ownership.
  4. 422 → Validation error. Fix the request parameters and retry.
  5. 5xx → Server error. Retry with exponential backoff.

Idempotency

Section titled “Idempotency”
  • Approve is idempotent — approving an already-approved post is safe
  • Reject is idempotent — rejecting an already-rejected post is safe
  • Send is NOT idempotent — attempting to send an already-sent post returns 422
  • Delete is idempotent — deleting a non-existent resource returns 404

Rate Limiting

Section titled “Rate Limiting”

See Rate Limits for current guidelines. Agents should:

  • Space requests at least 1 second apart
  • Use bulk endpoints instead of individual calls
  • Implement backoff on repeated failures

Security Considerations

Section titled “Security Considerations”
  • Never hardcode API keys in agent source code
  • Use least-privilege keys — create separate keys per agent with expiry dates
  • Revoke keys when an agent is decommissioned
  • Audit usage via the API key list in Settings
  • API keys can’t create other keys — a compromised key cannot escalate privileges
