All API requests require a Bearer token in the `Authorization` header. Poaster uses API keys — not OAuth — for programmatic access.

## API Key Auth

Include your API key in every request:

```
Authorization: Bearer po_live_your_api_key
```

When the server detects a `Bearer` token, it returns JSON responses instead of HTML redirects. Endpoints that don't accept API keys return a `403` error.

## Creating an API Key

API keys are managed in the Poaster web UI:

1. Log in at [my.poaster.app](https://my.poaster.app)
2. Navigate to **Settings** → **API Keys**
3. Enter a name and optional expiry date
4. Click **Create**
5. **Copy the key immediately** — the raw token is shown only once

## Key Properties

| Property | Details |
|----------|---------|
| **Format** | `po_live_` prefix followed by random characters |
| **Storage** | Raw token is shown only once at creation and cannot be retrieved later |
| **Expiry** | Optional — set an expiry date when creating the key |
| **Revocation** | Revoke anytime in Settings; key immediately stops working |
| **Tracking** | Usage can be monitored in the Settings → API Keys page |

## Available Endpoints

API keys work with the endpoints documented in the API Reference. Endpoints not listed there (Dashboard, Settings, Billing, OAuth flows) are web-only and reject API keys with `403`.

## Security

- **API keys cannot create other API keys.** The API key management endpoints are browser-only. A compromised key cannot escalate by creating additional keys.
- **Store keys securely.** Use environment variables or a secrets manager — never hardcode in source control.
- **Set expiry dates** for short-lived integrations.
- **Revoke immediately** if a key is compromised. Revocation is instant.

## Error Responses

| Status | Meaning | Response |
|--------|---------|----------|
| `401` | Invalid or missing API key | `{"error": "Unauthorized. Invalid or missing API key."}` |
| `403` | Endpoint doesn't accept API keys | `{"error": "Forbidden. This endpoint does not accept API key authentication."}` |
| `403` | Resource belongs to another user | `{"error": "Forbidden"}` |

### 401 vs 403

- **401** means the endpoint *does* accept API keys, but your token is missing, invalid, expired, or revoked
- **403** means the endpoint does *not* accept API keys at all — use the web UI instead
