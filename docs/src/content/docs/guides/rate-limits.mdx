## Rate Limits

To ensure fair usage and platform stability, please follow these rate limit guidelines:

## Recommended Limits

| Action | Recommended Rate |
|--------|-----------------|
| Read requests (GET) | Up to 60 per minute |
| Write requests (POST/PATCH/DELETE) | Up to 30 per minute |
| Bulk operations | Up to 10 per minute |
| Send operations | Up to 5 per minute |

## Best Practices

### Use Appropriate Intervals

Space your requests at least 1 second apart for write operations. For bulk operations, wait 5 seconds between batches.

### Implement Exponential Backoff

If you receive `429` or `5xx` errors, implement exponential backoff:

```python
import time
import requests

def api_call_with_retry(url, method="GET", max_retries=3, **kwargs):
    for attempt in range(max_retries):
        response = requests.request(method, url, **kwargs)
        if response.status_code == 429:
            wait = 2 ** attempt
            time.sleep(wait)
            continue
        return response
    return response
```

### Cache Responses

For workflows that poll for status changes, cache responses and only re-fetch when you expect a change (e.g., after triggering a job).

### Batch Operations

Use [bulk endpoints](bulk-operations/) instead of making individual requests for each post. One `bulk_approve` call is better than 50 individual `approve` calls.

## Rate Limit Headers

When rate limits are active, responses include standard headers:
- `X-RateLimit-Limit` — Request quota for the current window
- `X-RateLimit-Remaining` — Remaining requests in the current window
- `X-RateLimit-Reset` — Time (in seconds) until the quota resets

Check the [Poaster changelog](https://poaster.userjot.com/updates) for any updates to rate limit policies.
